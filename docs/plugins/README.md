# Плагины TermDock

> 🇬🇧 [English version](README.en.md)

Плагин добавляет в TermDock свои команды, панели и автоматизацию. Это обычная папка с HTML/JavaScript: никаких сборщиков и зависимостей не нужно, хватит текстового редактора.

Что может плагин:

- **команды** — в палитре (`Ctrl+Shift+P`), в меню вкладки, сервера, файла и сессии, по горячей клавише;
- **реагировать на терминал** — читать вывод, вводить текст (например, автоматически отвечать на вопросы);
- **работать с сервером** — выполнять команды в фоне (как это делает виджет нагрузки), читать и записывать файлы по SFTP;
- **рисовать свой интерфейс** — панель справа, панель под терминалом, отдельное окно;
- **хранить свои данные** — настройки, историю, что угодно в JSON.

Плагины работают в изолированной песочнице: они не видят пароли, ключи, файлы на вашем компьютере и не могут выходить в интернет. Всё, что касается серверов, плагин получает только с **разрешения**, которое пользователь подтверждает при установке.

## Быстрый старт

1. Создайте папку `my-plugin` с двумя файлами.

   `plugin.json`:

   ```json
   {
     "id": "my-plugin",
     "name": { "ru": "Мой плагин", "en": "My plugin" },
     "version": "1.0.0",
     "apiVersion": 1,
     "main": "main.js",
     "contributes": {
       "commands": [{ "id": "hello", "title": { "ru": "Поздороваться", "en": "Say hello" } }],
       "menus": { "session": [{ "command": "hello" }] },
       "keybindings": [{ "command": "hello", "key": "Ctrl+Alt+H" }]
     }
   }
   ```

   `main.js`:

   ```js
   termdock.commands.register("hello", async (ctx) => {
     const session = (await termdock.sessions.list()).find((s) => s.paneId === ctx.paneId);
     termdock.ui.toast(`Привет, ${session ? session.serverName : "мир"}!`);
   });
   ```

2. В TermDock: кнопка с пазлом в заголовке окна → **«Управление плагинами…»** → **«Установить из папки…»** → выберите `my-plugin`.
3. Нажмите `Ctrl+Alt+H` или откройте палитру `Ctrl+Shift+P` и найдите «Поздороваться».

**Как разрабатывать удобнее.** Установка копирует папку. Чтобы правки сразу подхватывались, держите плагин прямо в папке плагинов: «Управление плагинами» → **«Папка плагинов»** откроет её (`~/.config/dev.termdock.app/plugins/` в Linux, `%APPDATA%\dev.termdock.app\plugins\` в Windows). Положите туда свою папку, включите плагин галочкой, а после правок нажимайте **«Перезагрузить»**.

## Как устроен плагин

```
my-plugin/
  plugin.json      описание: id, название, разрешения, команды, панели
  main.js          фоновый код: работает всё время, пока плагин включён
  panel.html       (необязательно) страницы панелей
  panel.js
  icon.svg, …      любые другие файлы плагина
```

- **Фоновый код** (`main` в plugin.json) загружается в скрытый фрейм при запуске TermDock. Здесь регистрируют команды и подписываются на события.
- **Панели** — обычные HTML-страницы. TermDock сам добавляет в каждую объект `termdock` и тему оформления (тёмные цвета, шрифты, стили кнопок и полей), так что страница сразу выглядит «родной». Свои стили можно писать поверх, CSS-переменные темы: `--bg`, `--bg-1`, `--text`, `--muted`, `--accent`, `--line`, `--ok`, `--warn`, `--err`, `--mono`. Для кнопок есть классы `primary` и `danger`.
- Фоновый код и каждая панель — **разные страницы**, у них нет общих переменных. Общаются они через [хранилище](#данные-плагина-storage): когда одна страница меняет данные, остальные получают событие `storage.changed`.
- Скрипты и стили подключайте **из файлов плагина** (`<script src="panel.js">`); встроенные `<script>…</script>` тоже работают. Загрузить что-то из интернета нельзя: зависимости кладите в папку плагина.
- Все вызовы `termdock.*`, кроме `on`, `commands.register` и `i18n.t`, **асинхронные** и возвращают `Promise`. Если действие не удалось (нет разрешения, сессия закрыта), промис отклоняется с понятной ошибкой.

## plugin.json

| Поле | Обязательно | Описание |
|---|---|---|
| `id` | да | Уникальный идентификатор: 2–64 символа `a-z`, `0-9`, `-`, `_`, `.`. Совпадает с именем папки после установки. |
| `name` | да | Название. Строка или `{ "ru": "…", "en": "…" }`. |
| `version` | да | Версия плагина, например `"1.2.0"`. |
| `apiVersion` | да | Версия API TermDock. Сейчас `1`. Плагин с большей версией TermDock откажется устанавливать. |
| `main` | нет | Файл фонового кода, по умолчанию `main.js`. |
| `description` | нет | Описание (строка или `{ ru, en }`), видно в списке плагинов и при установке. |
| `author`, `homepage` | нет | Автор и ссылка. |
| `permissions` | нет | Список [разрешений](#разрешения). Без них плагин может только показывать команды, панели и уведомления. |
| `contributes` | нет | Что плагин добавляет в интерфейс (ниже). |

Все тексты для интерфейса (`name`, `description`, `title`) можно писать строкой или объектом с переводами: `{ "ru": "Обновить", "en": "Refresh" }`. TermDock покажет нужный язык.

### contributes.commands

```json
"commands": [
  { "id": "deploy", "title": { "ru": "Задеплоить", "en": "Deploy" } }
]
```

Команда появляется в палитре (`Ctrl+Shift+P`). Её обработчик регистрирует фоновый код: `termdock.commands.register("deploy", fn)`.

### contributes.menus

```json
"menus": {
  "tab":     [{ "command": "deploy" }],
  "session": [{ "command": "deploy" }],
  "server":  [{ "command": "ping" }],
  "file":    [{ "command": "checksum", "side": "remote" }]
}
```

| Меню | Где | Что получает команда (`ctx`) |
|---|---|---|
| `tab` | правый клик по вкладке | `paneId` (активная панель вкладки), `paneIds` (все панели) |
| `session` | кнопка «Плагины» в строке над терминалом | `paneId` |
| `server` | правый клик по серверу в списке | `serverId` |
| `file` | правый клик по файлу | `paneId`, `side` (`"local"` / `"remote"`), `paths`, `dir` |
| палитра и горячие клавиши | — | `paneId` активной сессии (или `null`) |

У пунктов меню файлов можно указать `"side": "local"` или `"remote"`, чтобы показывать их только для файлов компьютера или сервера.

### contributes.keybindings

```json
"keybindings": [{ "command": "deploy", "key": "Ctrl+Alt+D" }]
```

Нужен хотя бы один модификатор (`Ctrl`, `Alt`) или клавиша `F1`–`F12`: обычные клавиши принадлежат терминалу. `Ctrl` на macOS также срабатывает как `Cmd`. Сочетания TermDock важнее сочетаний плагинов.

### contributes.panels

```json
"panels": [
  { "id": "rules", "title": "Правила", "location": "sidebar", "entry": "rules.html" },
  { "id": "info",  "title": "Сервер",  "location": "session", "entry": "info.html" },
  { "id": "about", "title": "О плагине", "location": "dialog", "entry": "about.html", "width": 420, "height": 260 }
]
```

| `location` | Где показывается | Как открыть |
|---|---|---|
| `sidebar` | справа, как панель «Скрипты» | кнопка с пазлом в заголовке окна, `termdock.ui.openPanel(id)` |
| `session` | под терминалом конкретной сессии, вместо файлов | кнопка «Плагины» в строке сессии, `termdock.ui.openPanel(id, paneId)` |
| `dialog` | отдельное окно поверх приложения (`width`, `height` в пикселях) | кнопка с пазлом, `termdock.ui.openPanel(id)` |

Панель сессии знает свою сессию: `termdock.context.paneId`.

## API: объект termdock

Объект `termdock` есть в фоновом коде и в каждой панели. Готовые типы для подсказок в редакторе — [termdock.d.ts](termdock.d.ts).

### Общее

| | |
|---|---|
| `termdock.ready` | Промис: TermDock передал данные плагина. До него `plugin`, `language`, `context` ещё не заполнены (вызовы делать можно). |
| `termdock.plugin` | `{ id, name, version }` |
| `termdock.language` | Язык интерфейса: `"ru"` или `"en"` |
| `termdock.permissions` | Выданные разрешения (пользователь мог снять часть галочек) |
| `termdock.context` | Для панели сессии — `{ paneId }`, иначе `{}` |
| `termdock.i18n.t(text)` | Выбирает перевод: `t({ ru: "Да", en: "Yes" })` |

### События: termdock.on(событие, функция)

Возвращает функцию отписки.

| Событие | Данные | Когда |
|---|---|---|
| `terminal.output` | `{ paneId, text }` | Вывод терминала (текст с escape-последовательностями цветов), пачками раз в ~50 мс. **Нужно `terminal.read`.** |
| `session.connected` | `Session` | Сессия подключилась |
| `session.closed` | `{ paneId }` | Сессия отключилась или закрыта |
| `session.focus` | `Session` или `null` | Пользователь переключился на другую сессию (или на главный экран) |
| `storage.changed` | `{ key }` | Другая страница этого плагина изменила его данные |
| `language` | `"ru"` / `"en"` | Сменился язык интерфейса |
| `context` | объект | Сменился контекст панели |

`Session` — это `{ paneId, serverId, serverName, host, port, username, status, focused }`. `paneId` — постоянный идентификатор панели терминала: его передают во все функции работы с сессией.

### Команды

```js
termdock.commands.register("deploy", async (ctx) => {
  // ctx зависит от того, откуда вызвана команда (см. contributes.menus)
});
```

Если обработчик выбросит ошибку или вернёт отклонённый промис, TermDock покажет её пользователю.

### Интерфейс: termdock.ui

| Функция | Результат |
|---|---|
| `toast(текст, вид?)` | Уведомление; `вид`: `"info"`, `"success"`, `"error"` |
| `confirm(заголовок, текст?)` | `true` / `false` |
| `prompt(заголовок, подпись?, значение?)` | Строка или `null`, если отменили |
| `openPanel(idПанели, paneId?)` | Открывает панель из plugin.json |
| `closePanel()` | Закрывает панель, в которой выполняется код |

К заголовкам уведомлений и диалогов TermDock добавляет название плагина: пользователь всегда видит, кто спрашивает.

### Сессии и терминал

| Функция | Разрешение | |
|---|---|---|
| `sessions.list()` | — | Все открытые сессии (`Session[]`) |
| `sessions.active()` | — | Активная сессия или `null` |
| `terminal.send(paneId, текст)` | `terminal.write` | Ввод в терминал, `"\r"` — Enter |

```js
// Перезапустить nginx в активной сессии
const s = await termdock.sessions.active();
if (s) await termdock.terminal.send(s.paneId, "sudo systemctl restart nginx\r");
```

### Команды на сервере: termdock.server.exec

```js
const r = await termdock.server.exec(paneId, "df -h /", { timeout: 15000 });
// r = { code: 0, stdout: "…", stderr: "" }
```

Нужно разрешение **`server.exec`**. Команда выполняется в отдельном канале SSH — в терминале её не видно, на ввод пользователя она не влияет. Таймаут по умолчанию 30 секунд (от 1 секунды до 10 минут), вывод — до 10 МБ. Сессия должна быть подключена.

На сервере команда запускается через оболочку входа пользователя. Если она может быть `fish` или `csh`, оборачивайте сложные команды в `sh -c '…'`.

### Файлы на сервере: termdock.files

| Функция | Разрешение | |
|---|---|---|
| `files.home(paneId)` | `files.read` | Домашняя папка |
| `files.list(paneId, путь)` | `files.read` | Содержимое папки: `{ name, path, isDir, isLink, size, modified, mode }[]` |
| `files.readText(paneId, путь)` | `files.read` | Текст файла (кодировка определяется сама), до 5 МБ |
| `files.writeText(paneId, путь, текст)` | `files.write` | Записывает файл в UTF-8 (создаёт или заменяет) |

Пути на сервере — всегда в формате POSIX (`/etc/nginx/nginx.conf`).

### Список серверов: termdock.servers.list()

Нужно разрешение **`servers.read`**. Возвращает сохранённые серверы: `{ id, name, host, port, username, group, color }[]`. Паролей, ключей и путей к ключам там нет никогда.

### Данные плагина: termdock.storage

Собственное хранилище плагина: любые JSON-значения, до 5 МБ всего. Сохраняется между запусками, удаляется вместе с плагином.

```js
await termdock.storage.set("rules", [{ when: "[Y/n]", reply: "y" }]);
const rules = (await termdock.storage.get("rules")) || [];
await termdock.storage.delete("rules");
const everything = await termdock.storage.all();
```

Когда одна страница плагина меняет данные, остальные получают `storage.changed` — так панель настроек сообщает фоновому коду, что пора перечитать правила.

### Прочее

| Функция | Разрешение | |
|---|---|---|
| `clipboard.writeText(текст)` | `clipboard.write` | Копирует в буфер обмена |
| `openUrl(ссылка)` | `openUrl` | Открывает `http(s)`-ссылку в браузере |

## Разрешения

Плагин перечисляет нужные разрешения в `permissions`. При установке TermDock показывает их списком, и пользователь может снять любые галочки. Опасные помечены знаком ⚠. Вызов без выданного разрешения отклоняется с ошибкой: проверяйте `termdock.permissions` и объясняйте пользователю, чего не хватает.

| Разрешение | Что даёт |
|---|---|
| `terminal.read` | Событие `terminal.output` — видеть всё, что выводится в терминалы |
| `terminal.write` ⚠ | `terminal.send` — вводить текст и команды |
| `server.exec` ⚠ | `server.exec` — выполнять команды на серверах в фоне |
| `files.read` | Читать файлы и папки на серверах |
| `files.write` ⚠ | Записывать файлы на серверах |
| `servers.read` | Видеть список сохранённых серверов (без паролей) |
| `clipboard.write` | Копировать в буфер обмена |
| `openUrl` | Открывать ссылки в браузере |

Без разрешений плагин всё равно может: добавлять команды, меню, горячие клавиши и панели, показывать уведомления и диалоги, видеть список открытых сессий и хранить свои данные.

Просите только то, что действительно нужно: короткий список разрешений — главная причина, по которой пользователь решит установить плагин.

## Безопасность и ограничения

Каждая страница плагина работает в **изолированном фрейме** (`sandbox` без `allow-same-origin`), со своей политикой безопасности:

- у плагина **нет доступа к TermDock**: ни к его окну, ни к хранилищу, ни к внутренним командам Tauri; всё идёт через `termdock`, а TermDock проверяет каждое действие по выданным разрешениям;
- **нет сети**: `fetch`, `XMLHttpRequest`, WebSocket и загрузка скриптов или картинок из интернета заблокированы;
- **нет** `localStorage`, `cookie`, `alert` / `confirm` / `prompt`, всплывающих окон и переходов по ссылкам — используйте `termdock.storage`, `termdock.ui.*` и `termdock.openUrl`;
- плагин **не видит** пароли, passphrase и ключи, а также файлы на компьютере пользователя.

Ограничения:

| | |
|---|---|
| Размер плагина | до 50 МБ и 2000 файлов |
| Данные плагина (`storage`) | до 5 МБ |
| `server.exec` | вывод до 10 МБ, таймаут от 1 с до 10 мин |
| `files.readText` | файлы до 5 МБ |
| `terminal.output` | приходит пачками раз в ~50 мс, не больше 1 МБ на сессию за пачку |

Даже с изоляцией плагин с разрешениями `terminal.write`, `server.exec` или `files.write` может сделать на сервере всё, что можете вы. Поэтому устанавливайте плагины только из источников, которым доверяете.

## Отладка

- **Ошибки в командах** TermDock показывает уведомлением с названием плагина.
- **Консоль.** Запустите TermDock из исходников в режиме разработки (`npx tauri dev`) и откройте инструменты разработчика (обычно `Ctrl+Shift+I`, в Windows также `F12`). Фреймы плагинов есть в списке контекстов консоли (`tdplugin://localhost/<id>/…`, в Windows `http://tdplugin.localhost/<id>/…`), там же их `console.log` и ошибки.
- **Перезагрузка.** «Управление плагинами» → **«Перезагрузить»** заново загружает код всех плагинов. Открытые панели тоже перезагружаются.
- **Не загружается?** При установке ошибка в plugin.json показывается сразу. Если плагин лежит прямо в папке плагинов, он всё равно появится в списке — с описанием проблемы красным.

## Как поделиться плагином

Упакуйте папку плагина в `.zip` (plugin.json может лежать в корне архива или в одной папке внутри) — его можно установить через **«Установить из .zip…»**. При обновлении поднимите `version`: установка поверх заменит старую версию, а данные плагина (`storage`) сохранятся.
